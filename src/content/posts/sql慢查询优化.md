昨天下午叫我去优化一个查询接口，传入的参数比较简单，但是查询一个数据要等16秒，接着就开始了我的优化之路。
## 定位接口代码
要先知道接口发送了什么数据，发送到哪个接口，直接在浏览器前端f12即可，看看发送的载荷和接口地址
## 找慢的位置
我给代码打上断点，去看一下慢在哪里，到service的时候，我当时就被震惊了，感觉我一个实习生都写不出这种代码。
下面示例：
```
	//就是先根据传入的参数去数据库中查出一堆对象，然后通过for循环获取list里面每个对象的id再去查数据库
	list<dto> one  = dao.select(param)
	for(){
		dto2 two = dao.select(one.getid)
	}
```

总之要查n+1次数据库
## 优化思路
我的优化思路呢，就是先去把这个for循环去掉

我把上一条查询出来的数据用stream流的方式处理所有的id，封装成一个list集合，再用另外一条sql接收这个list集合再去查一遍

这样的方式只需要查两遍sql，但是还是很慢，需要10秒

接下来的话，我是想着怎么去优化sql语句的，它关联的表很多，，查询出来确实要慢，它之前写的sql语句我觉得存在重复查询，而且嵌套了三层子查询
叫ai帮我改了一下改为联查，但对查询速度提升比较有限

我去问带我的师傅，他叫我去explain一个查询慢的sql语句，看他有没有走索引

我explain后看三个字段，type，key，extra字段，去判断索引类型和是否有走索引

接着在对应的表建立合适的索引，这样一通操作下来，查询时间为1.4秒
